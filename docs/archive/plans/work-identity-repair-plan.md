## 1. 已确认的问题和修复目标

本机项目 `W4245234602` 的快照有 95 个节点。其中以下记录的题名仅大小写不同，作者、年份、类型、期刊、卷期和页码一致：

| DOI | 10.2307/415601 | 10.1353/lan.1986.0014 |

| 作者、年份 | Johanna Nichols，1986 | Johanna Nichols，1986 |
| 出处 | Language 62(1): 56–119 | Language 62(1): 56–119 |
| 参考文献 ID 数 | 16 | 49 |

两份参考列表交集为 14 个 ID。按当前已知别名映射合并、去重和去掉自身后，应保留 51 个参考文献 ID，不能简单删掉其中一个节点的数据。

修复后的约定：一张研究图中，同一已确认作品只占一个可见节点、一个采样名额和一份用户状态；源记录、不同 DOI、获取来源和原始引用证据均可追溯。不同研究项目仍可围绕同一作品独立保存。

## 2. 当前代码缺口

- `src/neighborhood.ts`：`withoutSeedDuplicate` 和 `identityKey` 只识别相同 ID/DOI；采样后的候选选择不识别不同 DOI 的同一作品。
- `src/neighborhood.ts`、`src/graph-edit.ts`：深挖、补充候选、并入和恢复深挖成员主要按 OpenAlex ID 判断是否已存在或已排除。
- `src/project-state.ts`：快照直接保存和恢复节点；项目查找只识别种子主 ID/主 DOI；阅读、暂存、排除、深挖记录和视图选中项都引用具体 ID。
- `src/embed-mount.ts`：嵌入另有建图、二层扩展和内存缓存入口；仅修改主面板不能覆盖这些路径。
- `src/doi-path.ts`、`src/vault-note.ts`、`src/export-graph.ts`：路径端点、笔记索引和导出也依赖主 ID/主 DOI。

## 3. 一个共用的作品识别模块

新增 `src/work-identity.ts`，供取数、图谱修改、项目恢复和查询共同调用。它负责识别、别名解析、图谱投影和合并依据；界面层不自行比较题名或 DOI。

对外只暴露必要能力：从源记录建立作品分组；将任一已知 ID/DOI 解析为项目内代表 ID；将源图投影为作品图。实现采用纯数据输入/输出，不发网络请求，不写插件设置，不操作 DOM。

### 3.1 自动合并规则

1. 相同来源 ID：同一源记录，更新元数据时保留冲突来源。
2. 标准化 DOI 相同：归属同一作品。严重的题名或类型冲突单独记录为元数据异常，不能把两个被引数相加。
3. DOI 不同：首版仅对期刊论文启用严格书目信息匹配。要求题名、完整且非空的有序作者名单、年份、期刊、卷号、起止页全部有值且一致；期号在两边都有值时必须一致；类型冲突阻止合并。此规则覆盖 Nichols 案例。
4. 缺字段、作者截断、模糊相似题名、预印本与正式出版、译本、再版、书与章节、书评与被评作品：保留为独立作品。本轮不增加模糊自动合并。

文本只做 Unicode NFKC、大小写、空白和等价连字符的规范化，保留题名中有意义的符号。不用子串包含、编辑距离或年份容差决定自动合并。

分组必须整体一致：A 与 B、B 与 C 的局部匹配不能绕过 A 与 C 的元数据冲突。记录匹配依据和规则版本，结果不依赖输入顺序。

### 3.2 代表记录与来源保存

- 已有项目保留原有种子 ID 作为项目锚点，避免项目键和书签变动。
- 非种子分组优先沿用该项目已保存的代表 ID；新分组按固定规则选择代表，不能因本次返回顺序改变。
- 保存成员 ID、全部 DOI、合并依据、规则版本，以及每条源记录的元数据和引用来源。别名查询覆盖整个分组。
- 展示题名和主 DOI优先沿用代表记录；缺失字段可由兼容成员补充，并保存字段来源。被引数不相加、不默认取最大；展示代表记录值，来源详情可查看各条记录的值。
- 支持项目内的“保持分开”覆盖项，从详情中的来源区域进入。覆盖项持久化，后续刷新不再次合并；原始记录仍可用于重新生成图谱。

## 4. 图谱、证据和评分的处理

保留源记录和源引用列表作为依据，作品图是经过身份映射的派生结果。快照可继续缓存派生图以便快速打开，但任何变化均能从源数据重新生成，缓存不成为另一个可独立修改的数据源。

处理顺序固定为：记录识别 → 候选按作品分组 → 按作品分配节点名额 → 获取已选作品成员的必要详情 → 引用 ID 归一化 → 证据合并 → 重算关系与评分 → 布局和绘制。

- 同一作品多条记录的参考文献取并集；引用端点映射为代表 ID。映射后相同端点对只计一次直接引用；自己指向自己的边不进入作品图，原始来源记录保留。
- 同一施引作品有多个来源记录时，作为一份共被引上下文处理，其引用列表先合并。否则共被引次数会被重复记录放大。
- 不直接相加旧边权、共享参考数或共被引数。用归一后的引用集合重新计算结构分、图内引用次数、先验/衍生列表和可视化边。
- 引用证据按归一后的有向端点合并，来源、引用语境、原始端点、意图和可信度保留；存在冲突时沿用证据模块的明确合并规则并记录冲突。
- 重新计算受影响的语义分及全图综合分，保持现行结构/语义口径。不同模型的向量不平均；无兼容向量时按现有本地语义降级流程处理。
- 对新图在 MMR 和名额选择前合并候选。已确认别名成员的详情请求纳入现有请求预算；预算不足保留“引用数据部分缺失”的状态，不丢弃已获得列表。
- 对旧项目迁移只处理本地已有数据，不联网补齐节点。该案例仅合并这对节点时，95 个可见节点变为 94 个；边数根据重算结果确定。

## 5. 所有工作流接入同一规则

| 路径 | 必须达到的行为 |
| --- | --- |
| 初次建图和重新加载 | 采样按作品去重，别名不占额外名额；刷新不改变已保存代表 ID |
| 深挖和二层扩展 | 与现有、已排除作品和当批候选比较；命中别名可补证据，但不算新增节点 |
| 深挖成员恢复 | 已在图内的作品不再并入另一条记录；区分新增作品数、补充记录数和失败数 |
| 暂存、阅读、排除和恢复 | 写入作品状态；从任一别名操作得到一致结果；排除后其他别名不能重新进入 |
| 视图和撤销 | selectedId、批次父节点、成员 ID、撤销快照均能解析别名；撤销按原操作批次恢复 |
| 图内搜索和 DOI 路径 | 任一已知 ID/DOI 可定位同一作品；路径移除身份合并造成的零长度/自环步骤 |
| 文献笔记和导出 | 所有别名可找到已有笔记；每个作品导出一条，保留主标识和可选别名字段 |
| 主面板和嵌入 | 共用识别和图谱投影；嵌入二层扩展、缓存命中也必须经过同样的校验 |

项目查找优先精确匹配原项目种子键，其次匹配已知别名。一个 DOI/ID 若对应多个独立研究项目，展示项目选择，不把项目内容自动合成或覆盖。不同 DOI 只有在已有可信别名依据或获取到足够元数据后才能归入同一项目，不能从未知 DOI 本身推断同一作品。

已存在的多份文献笔记保留；别名查询若命中多个文件，显示选择，禁止自动改写、合并或删除笔记。

## 6. 状态冲突与旧项目迁移

快照采用明确的新版本，并保留旧版本读取适配。项目容器无需因快照变化另建项目体系。新版本保存源记录、身份分组/覆盖项、合并依据和规则版本。

迁移流程：

1. 在本地私有插件数据位置创建可恢复的迁移前备份，不把含服务凭据的完整设置文件写入仓库或公开报告。
2. 在副本上读取旧快照，建立身份映射，生成作品图，并重映射引用证据、深挖父节点与成员、状态和保存视图 selectedId。
3. 阅读、暂存、排除分别保存字段更新时间，后续冲突按各字段最后一次明确操作处理。旧记录只有整体 updatedAt 时，选择最近记录作为初始结果并保留冲突原值和迁移日志；不能用“已读优先”或布尔并集覆盖用户可能做过的回退/移除。
4. 种子始终不能被排除；别名上的旧排除记录保留在日志中。收藏、阅读状态继续有效。合并后主界面展示一次迁移结果，存在状态冲突时提供查看和纠正入口。
5. 保留项目名称、种子键、命名视图、布局模式、筛选、侧栏和相机设置；节点身份映射后重算拓扑并执行一次布局更新。不会承诺合并后每个节点像素位置完全不动。
6. 校验通过后保存新快照；失败保留原快照和错误信息，不写半份迁移数据。重复打开和重复保存必须幂等。

跨打开窗口的项目写入需要先读取最新项目再合并本次操作，迁移和普通自动保存不能互相覆盖。对保存失败、退出中断、两个视图同时打开同一项目安排专门回归检查。

回滚分两类：撤回某个作品合并时用原始记录和“保持分开”覆盖项重建；回退插件版本时恢复迁移前备份，避免旧版无法理解新快照。回滚不能覆盖备份之后新产生的研究操作而不提示。

## 7. 嵌入缓存与刷新

- 共用身份规则版本进入嵌入缓存键；规则、项目身份、覆盖项或状态变化时，使受影响缓存失效。
- 缓存中保存不可被界面直接修改的源数据/快照；每次渲染派生独立图对象，防止一个嵌入的排除或证据补充污染另一个。
- 异步查询、证据补充和迁移沿用 generation/graph 身份检查；旧请求不得写回已经切换项目或改变身份映射的图。
- 图谱更新和状态更新分别发出正确刷新信号；一次合并只触发一次必要的关系重算与布局更新。

## 9. 验收清单

- Nichols 样本：两个 ID/DOI 都定位到同一作品；只出现一个种子节点；仅处理这对记录时显示 94 个节点；参考列表按当前样本保留 51 个去重 ID；两份源记录仍可查看。
- 数值：引用边方向正确；同一 citing/cited 作品对只计一次；同一施引作品不重复计入共被引；被引数不相加；评分、先验/衍生列表与详情依据一致。
- 反例：不同作者、年份、卷页、期号冲突、不同作品类型和缺少必要字段不触发跨 DOI 自动合并；短题名、符号题名和 Unicode 差异有专门样本。
- 工作流：主面板与嵌入；新建/重载/保存视图/重启/断网；深挖/排除/恢复/暂存/撤销；别名 DOI 查询/文献笔记/表格和 BibTeX 导出均覆盖。
- 状态：合并前两条记录有不同阅读/暂存/排除状态；恢复视图曾选中别名；深挖批次父节点是别名；都要给出确定结果并保留冲突依据。
- 数据安全：迁移失败、写入失败、重复迁移、旧异步请求晚返回、多个打开视图同时保存不会破坏原项目；原始快照和合并前记录可恢复。
- 性能：使用现有 100/300 节点与深采样基线比较身份匹配、关系重算和首屏耗时；优先按字段索引候选组，避免对全部采样结果做无界两两比较。不得引入逐候选联网核验。
- 本机部署：构建检查通过；安装目录 main.js/manifest/styles 与目标构建对应；关闭再启用插件或重启后，通过真实的别名查询和单种子画面确认新版已经运行。文件哈希一致或进程启动时间都不能单独作为运行验收结论。
