# Research Connected 完整改进方案

## 1. 产品定位与方案边界

Research Connected 是一个运行在 Obsidian 里的**单篇种子论文相似性地图**：用户输入 DOI、OpenAlex ID 或标题，在主面板里探索相似论文；也可以把 3D 图谱嵌入笔记，在阅读上下文中查看。它不是通用数据仪表盘，不是引用卡片列表，也不应把相似关系解释成引用或真实学术影响。[项目定位](/Users/junwei/开发/research-connected/README.md:1) [入口与嵌入说明](/Users/junwei/开发/research-connected/README.md:52)

改进要围绕两条不同的使用路径：

- **主面板：深入探索。** 允许更多筛选、关系检查和研究操作。
- **笔记内嵌：辅助阅读。** 优先保留阅读空间和图谱上下文，避免塞入完整控制面板。

因此，不能为了“功能一致”强迫两种视图变成同一套 UI。当前两套渲染管线和详情实现也应作为真实成本纳入计划，而不是当作小型样式改动处理。

## 2. 已有能力：作为基线，不重复开发

当前产品已经具备许多原方案中列出的功能：

- 种子论文有双环与光晕标记。
- 图中包含不同关系类型，弱边默认隐藏，并有边证据说明。
- 详情中已有关系、来源及相关警告信息；Semantic Scholar 意图和 Influential 字段有数据才显示。
- 有筛选／图例、年份控件、先验和衍生列表。
- 桑基图和弦图属于次级分析视图。
- 支持 BibTeX、YAML、表格导出和写入笔记。
- LLM 默认关闭；关闭时不显示相关入口、不生成内容、不发送请求。
- 嵌入图谱支持尺寸、位置和布局参数，且应服务于笔记上下文。[项目交互说明](/Users/junwei/开发/research-connected/README.md:112)

因此，改进重点不是重做图例、导出或关系信息，而是补足**关系语义的一致表达、使用口径和两条渲染管线的边界**。

## 3. 目标与验收原则

改进后，用户应能在不误读图谱的前提下完成：

1. 看出图谱围绕哪篇种子论文。
2. 理解节点为什么出现在图里。
3. 区分相似关系和直接引用证据。
4. 查看证据来源和当前采样范围。
5. 从探索结果回到论文详情、笔记或下一步操作。

可视化改动还必须满足：

- 不能仅靠 hover 才解释关键编码。
- 不改变默认相似性地图的产品定位。
- 详情和分析不能把不完整数据包装成完整学术史。
- 不明显损害 300 节点规模下的构建体验、拖动和缩放流畅度。
- 嵌入视图不应破坏笔记正文的阅读节奏。

## 4. 增量实施清单

| 优先级 | 改进项 | 当前基线 | 真正要做的增量 |
|---|---|---|---|
| P0 | 关系语义与口径 | 详情已有关系、方向、来源等信息 | 统一关系标签；在没有直接引用时明确写出“这是图谱相似关系，不代表直接引用”；统一分析页的范围和空状态文案 |
| P0 | 两套渲染管线边界 | 主面板与笔记内嵌的视图、交互和详情实现不同 | 明确每项能力在哪个场景实现；暂存和 DOI 路径首版仅在主面板，不要求内嵌同步 |
| P1 | 图谱可读性验收 | 已有节点标记、边类型、图例和证据提示 | 检查图例是否容易发现、相似关系和引用关系能否分辨、选中节点后是否仍保有全图上下文 |
| P1 | 视觉与性能基线 | 有离线预览与测试基础 | 固定关键场景截图；同时记录 300 节点构建时间和图谱交互帧率。窄屏是验收维度，不另起一项适配工程 |
| P2 | 探索交互 | 已能选节点、看详情、查看到种子的路径 | 评估是否需要“聚焦此论文邻域”；若做，需能轻松回到全图，并与筛除节点区分 |
| P2 | 暂存／持久化 | 尚未实现；Obsidian 插件已有本地数据持久化机制 | 增加待读列表，持久化并按种子论文分组；首版只做主面板，并支持移除和导出 |
| P3 | 两 DOI 路径 | 尚未实现；用户重新纳入规划 | 作为独立命令面板功能；优先复用已抓取引用列表，标明预算、方向、长度和来源；不宣称全局最短 |
| 不做 | 作者／机构网络 | 已明确排除 | 不纳入本次及后续实施清单，除非用户另行改变范围 |

### P0：统一关系标签与口径文案

先用现有数据整理一套统一标签，覆盖：

- 直接引用，以及方向。
- 双源确认或单源来源。
- 共被引／文献耦合等相似关系。
- 仅有相似关系、无直接引用证据的情形。
- Semantic Scholar 返回的引用意图或 Influential 信息。

详情不必把所有来源信息重复堆叠；应让用户能快速回答“是什么关系、方向是什么、来源是什么”。关键证据仍在详情区域展开查看。

分析页补充简短固定口径，例如：“仅统计当前可见节点之间的直接引用；不代表完整学术史或实质影响。”空状态要解释是当前图谱／筛选范围内没有可绘制关系，而不是误导为领域中没有关系。

**验收：**任意选中关系时，都能区分“相似”与“引用”；单源和双源不靠颜色单独表达；筛选后分析页范围仍清楚。

### P0：决定面板和嵌入的功能边界

原则上：

- **主面板**承载深入探索、暂存、未来的 DOI 路径。
- **笔记内嵌**保持轻量阅读和地图浏览，保留目前适合嵌入的筛选、详情及图谱能力。
- 不为追求代码复用而贸然抽象详情组件；先评估共享组件能否避免 UI 与数据语义重复，而不增加渲染层耦合。

类似证据标签若两处都显示，需要分别验收，但不代表两处都要增加完整研究工具。

**验收：**每项新能力都有明确的“面板／嵌入／两者”范围；不会出现面板显示一种关系解释、嵌入显示另一种的语义分叉。

### P1：建立视觉和性能回归基线

使用现有离线预览固定典型状态：

- 初始空图。
- 一张典型种子图。
- 选中节点与展开详情。
- 图例／筛选打开。
- 分析页。
- 内嵌图谱。
- 窄宽容器。

同时记录 300 节点构建时间、拖动和缩放过程的性能。这样后续改标签、图例或聚焦行为时，能检查它是否挤压画布或影响交互，而不只判断截图“更好看”。

**验收：**视觉场景可重复，关键页面无溢出或遮挡；性能变化可比较。窄屏适配作为检查点，不另行重写现有适配。

### P1：检查，而不是重做，现有可视化编码

逐项核查：

- 种子标记是否足够醒目但不过度抢眼。
- 节点大小、颜色与边颜色的含义是否不冲突。
- 图例能否在用户需要时被发现。
- 选中或查看一条边时，是否看得到其关系说明和来源。
- 弱边隐藏是否能被发现与恢复。
- 选中节点后，用户是否仍然知道它在全图中的位置。

如果现有图例已足够，不增加第二套常驻图例；如果编码已经清晰，不引入新的色彩维度。

### P2：评估“聚焦邻域”是否值得做

Kumu 等网络工具的 focus 思路可以作为候选：围绕选中论文显示一跳或两跳邻域。但 Research Connected 当前已有到种子的路径高亮，不应直接照搬另一套功能。

只有在真实使用中发现图谱过密、路径高亮不够支持局部探索时，再实现邻域聚焦。必须：

- 区分聚焦和筛除。
- 明确显示当前聚焦中心和半径。
- 提供一键恢复全图。
- 只影响可见范围，不偷偷改变底层图谱或数据口径。

### P2：暂存列表

暂存列表服务于“发现了但暂时不决定如何整理”的阅读工作流，不是另一个复杂收藏系统。

首版只做：

- 按种子论文分组。
- 将论文加入／移出待读列表。
- 重启 Obsidian 后仍保留。
- 支持导出或写入笔记。
- 记录来源关系的简短说明，避免稍后只剩下题名、不记得为何保存。

暂存列表仅放主面板。先不扩展标签、协作、云同步和跨设备账户。

### P3：两 DOI 引用路径

保持独立命令面板入口，不并入默认图谱主工具栏。第一版优先在已抓取的引用列表上做受限搜索，避免为路径功能立即引入大型图遍历。

结果展示：

- 两端 DOI 和中间论文。
- 每条边的方向与数据源。
- 路径长度。
- 搜索预算、检查量及是否提前到达预算上限。
- 结果应表述为“预算内找到的路径”或“预算内未找到”，不暗示完整网络中的全局最短路径。

这项功能按 P3 规划；在数据覆盖、预算和路径口径未验证前，不提升为当前 UI 改版的核心工作。

## 5. 分阶段推进

1. **基线盘点与边界确定**：确认现有功能、两种渲染场景、截图／性能基线。
2. **P0 语义与文案**：统一关系标签，补齐相似关系提示和分析范围。
3. **P1 可视化验收**：查找图例、选中状态、全图上下文、窄屏和性能问题；只修真实问题。
4. **P2 主面板工作流**：按使用价值决定是否增加邻域聚焦；随后实现持久化暂存列表。
5. **P3 DOI 路径**：独立实现和验证搜索边界。
6. **回归验收**：重新跑固定截图和性能场景，确认笔记内嵌体验没有被主面板改动拖累。

## 6. 明确不纳入本轮的方向

- 作者／机构网络。
- 把产品改造成通用 BI 仪表盘或引用卡片列表。
- 为了功能一致而让嵌入具备完整主面板控制。
- 新增多个仅视觉不同、含义不清的图表。
- 把引用数或模型自评直接包装成“最重要论文”。
- 把预算内路径、采样到的引用或 LLM 总结描述为完整学术史。

**建议第一步只做 P0 和基线盘点**：它们能利用现有能力，工作范围小，同时能先确认真正的可视化问题在哪里；之后再依据实测决定是否值得开发邻域聚焦、暂存列表或 DOI 路径。
