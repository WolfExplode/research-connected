# Research Connected 综合改进方案（修订版）

本方案只规划**有实际增量的工作**，不重复建设项目已有的图谱、图例、关系证据、先验／衍生列表和导出能力。

## 产品目标

保留默认的种子论文相似性地图；补强关系的可解释性，并提供一个基于引用记录的时间脉络视图，帮助用户查看：

- 种子论文引用了哪些前置论文？
- 哪些后续论文引用了种子？
- 这些关系来自什么数据，覆盖范围有多大？

**引用关系不等于实质影响、方法继承或完整学术史。**视图名称和文案均避免超出数据能支持的结论。

## 已有能力：作为基线，不重复开发

当前已有种子标记、相似度布局、时间／放射布局、引用方向、共被引与文献耦合、关系说明、图例、路径高亮、先验／衍生列表、分析视图和数据质量警告。

需区分两类边：

- **相似地图的边**：为保持地图可读而筛选过，只保留种子近邻和其他节点的有限高分连接。
- **原始引用记录**：来自论文参考文献列表或采样到的施引论文数据，才可用于判断种子直接引用了谁、谁直接引用了种子。

因此，不能用当前可视化边集来代替完整引用记录。

## 改进一：补齐关系口径，不重做详情系统

在现有详情和边证据基础上补少量文案：

- 没有直接引用证据时，明确标注“图谱相似关系，不代表直接引用”。
- 引用关系继续显示方向与数据来源。
- 双源确认、单源记录、数据缺失和采样限制沿用现有证据，统一标签样式即可。
- 分析视图注明统计范围；空状态说明“当前图谱／筛选范围内无可绘制关系”。

精确相似度、共享参考文献数和共被引数继续放在详情中；不把它们提升为全图主视觉指标。

## 改进二：新增主面板“引用脉络”视图

这是对现有功能真正有意义的扩展，与默认相似地图分开呈现。

建议布局：

- 横轴：发表年份。
- 左侧分区：种子论文记录的参考文献。
- 中间：种子论文。
- 右侧分区：采样到、且数据源记录其引用种子的论文。
- 箭头：只表示明确的直接引用方向。
- 缺年份论文放入单独的“年份未知”区域。

视图必须依据**原始 `referenceLists`、引用证据和方向信息**构建，不能使用相似地图中经过稀疏化的边。数据展示应说明：

- 引用关系的来源。
- 当前采样到的论文和引用范围。
- 参考文献可能不完整、施引论文有预算上限。
- “引用了种子”不等于“受种子实质影响”。

不属于种子直接引用／施引的相似论文，不混进引用脉络图。当前先验／衍生列表仍保留原有“当前子图中的常见前置／后续工作”口径，不与新视图混为一类。避免重复入口的做法是：在现有相关区域提供“列表／引用脉络”切换，并清楚标注两者统计对象不同。

**首版只做在命令面板。**笔记内嵌继续作为轻量图谱阅读体验，不复制完整脉络视图。

## 改进三：评估默认相似地图，而非先改造它

默认力导向图的上下左右不是稳定语义。其位置会受初始化、连线弹簧和节点避让共同影响。因此：

- 不把空间距离称为精确相似度，也不解释默认布局的“左／右／上／下”。
- “时间”布局继续明确说明横轴年份、纵轴对数被引量；它不是引用脉络。
- “放射”布局继续说明半径是相似度提示，角度不是引用方向。
- 检查现有图例与提示是否足以解释这些区别；只修实测不清楚的部分。
- 可以借鉴 Kumu 的柔和配色和简短画布注释，但不直接加主题圈层，以免把相似性社区误读成研究主题。

“聚焦邻域”暂不实施。先验证已有悬停／选择高亮和到种子的路径高亮是否不足，再决定是否需要新状态。

## 实施阶段

### 阶段 0：基线与边界

- 固定主面板、嵌入、详情、边证据和分析页的离线回归场景。
- 记录 300 节点构建时间和交互性能。
- 明确哪些新增能力仅属于主面板。
- 窄屏作为验收场景，不单独立项重写已有适配。

### 阶段 1：关系口径小改

- 增加“相似关系，不代表直接引用”的明确提示。
- 统一关系标签。
- 补齐分析页范围说明与空状态。
- 不重复实现现有来源、证据、撤稿警告和图例。

### 阶段 2：引用脉络原型

- 以原始引用记录制作离线原型。
- 验证前置、种子、后续三个区域及年份未知处理。
- 处理同一论文在两侧出现、引用数据冲突、没有直接引用证据等边界情况。
- 明示数据源、采样预算和不完整性。

### 阶段 3：评审后决定是否正式加入

只有当用户能清楚区分“直接引用脉络”和“相似地图”，且数据范围能如实呈现，再将原型并入主面板。否则保留为独立实验视图或放弃，不为增加图表而增加图表。

### 阶段 4：独立的后续扩展

- **暂存列表**：可持久化并按种子分组，首版仅主面板。
- **两 DOI 路径**：继续作为 P3 独立功能；优先复用已有引用记录，显示方向、长度、来源和预算，不称全局最短路径。
- **LLM**：保持可选、默认关闭；输出与来源事实分开展示。
- **作者／机构网络**：不在范围内。

## 验收标准

1. 用户能分清默认图上的相似边与真实引用边。
2. 新脉络视图只把有直接引用证据的论文作为前置／后续节点。
3. 图中的方向、来源、年份与采样范围都有明确解释。
4. 不把引用关系说成影响力、方法继承或完整学术史。
5. 主面板和笔记内嵌的职责清楚，新增复杂视图不会破坏嵌入阅读体验。

**建议执行顺序：先完成阶段 0 和阶段 1，再用原始引用记录验证阶段 2。**这次修订最关键的变化是：引用脉络不再复用经过筛选的相似地图边，且明确和现有“子图常见前置／后续列表”区分。

## 附：代码核实修正（2026-10-03，执行前必读的基线事实）

对代码逐项核实后，以下四处与方案字面表述不同，执行时以本节为准：

1. **关系标签是新建，不是“统一现有样式”**。现状只有 sources 数组以“ + ”拼接显示（app.ts:572-575），`confidence: high/medium/low` 字段存在但 UI 不展示（citation-evidence.ts:17）。不存在“双源确认／单源记录／数据缺失”徽章式标签，阶段 1 需新建标签组件，工作量按新功能估算。
2. **先验／衍生列表的真实口径**：`priorWorks`/`derivativeWorks`（aggregates.ts:23-52）统计的是“当前可见子图（含年份滑块过滤后）内的互引频次”，阈值 ≥2、上限 15；衍生还会把未成为节点的 catalog 施引论文算入。它不是“种子直接引用”口径——这正是不能与新脉络视图混为一类的原因，评审与文案引用时以此为准。
3. **“到种子的路径”高亮只存在于嵌入端 3D 图**（graph-filter.ts:106-156 + filter-controls.ts:64-75）；2D 主面板调用时 `includePath=false`（map-canvas.ts:156-159），没有此能力。阶段 1 需先为主面板补齐路径高亮，阶段三才有东西可验证。
4. **阶段 0 的性能基线是全新设施**：仓库无任何性能测量与计时断言，preview fixture 只有 3 篇论文（preview/fixture.ts）。“记录 300 节点构建时间”需要先造 300 节点离线 fixture 并加计时，再谈回归。

另有一项实施约束记入阶段 2：脉络视图右侧“引用了种子的论文”只能来自按被引数排序的采样（standard 40 / extended 200 / deep ≤1000，见 neighborhood.ts 的 SAMPLE_TIERS），且仅入选节点与 ≤400 篇上下文施引（MAX_CONTEXT_CITERS）有可确认方向的 referenceLists——右区天然偏向高被引论文，视图文案必须如实说明这一覆盖偏差。左侧种子参考文献大多不在图节点集中，其年份／标题元数据需从 catalog 或批量补取获得，归属阶段 2 原型决策。

## 主面板专属能力（首版）

以下能力首版只入主面板，嵌入端保持轻量图谱阅读，不复制这些功能：

- **引用脉络视图**（改进二，阶段 2 原型）：基于原始引用记录的前置／种子／后续分区视图。
- **暂存列表**（阶段 4）：可持久化、按种子分组。
- **两 DOI 路径**（阶段 4，P3）：复用已有引用记录，显示方向、长度、来源与预算。
- **LLM 页签**（已存在，app.ts 研究脉络页签）：可选、默认关闭。

嵌入端继续只提供图谱浏览、筛选、详情证据、先验／衍生列表、分析视图与导出，不承担上述重交互能力。窄屏为人工验收场景，不单独立项。
