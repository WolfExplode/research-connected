# Research Connected 可视化与 UI 完整改进方案

## 目标与设计原则

这轮改进不追求让图谱“看起来更复杂”，而是让用户更快完成一条清楚的研究路径：

**找到种子论文 → 看懂图中关系 → 判断论文为何相关 → 验证证据 → 保存或继续探索。**

设计上遵循五条原则：

1. **图谱是主视图，分析是次级视图。**
2. **位置、颜色、大小、线条各自只表达明确含义。**
3. **每个关键结论都能回到数据来源或关系证据。**
4. **复杂功能按需出现，不让初始界面像控制台。**
5. **图谱中的发现能顺手进入 Obsidian 笔记或后续阅读流程。**

DOI 路径可作为独立功能入口继续规划；作者／机构网络不纳入本轮方案。LLM 保持可选：关闭时不出现相关入口和内容。

---

## 一、调整界面信息架构

### 当前主要问题

浏览页签、导出操作、布局与筛选等控件分布在不同区域，初次使用时不容易分辨“浏览内容”和“修改显示方式”。

### 建议结构

| 区域 | 主要职责 | 建议内容 |
|---|---|---|
| 顶部 | 开始或切换探索 | DOI／标题输入、构建图谱、进度与数据范围 |
| 中央 | 空间探索 | 默认图谱；缩放与适配；轻量图例 |
| 底部主导航 | 切换研究任务 | 图谱、先验工作、衍生工作、分析；仅在 LLM 启用时显示研究脉络 |
| 侧边视图控制 | 改变图谱表达 | 布局、着色、年份过滤 |
| 详情抽屉 | 核验当前选择 | 论文信息、关系理由、来源、引用语境、操作 |
| 更多操作 | 导出和写入 | BibTeX、YAML、表格、写入笔记 |

### 交互原则

- 将“视图设置”和“浏览页签”分开；避免操作控件与任务导航挤在同一条工具栏。
- 导出操作收进一个“导出／操作”菜单，常驻工具栏空间留给研究主流程。
- 保持“筛选／图例”抽屉，但在图谱边角展示始终可见的精简图例。
- 选中论文后，让详情标题区明确显示论文身份和选择状态；进入列表或分析后，也保留容易返回图谱的方式。
- 保留现有详情底部抽屉模型，避免同时引入左侧详情栏和底部详情栏两套模式。

## 二、重整图谱的视觉编码

### 建议的默认编码

第一版维持低认知负担，不同时使用太多视觉变量：

- **节点位置**：默认时间布局或当前默认布局；每种布局必须有一句用途说明。
- **节点颜色**：社区或年代二选一，不混用。
- **节点大小**：OpenAlex 被引量，并标明这是数据库计数，不代表质量或影响力。
- **边样式**：区分直接引用与相似关系；弱关系降权显示，不与直接引用同等醒目。
- **种子论文**：使用双环或清晰的专属形状，避免只靠颜色标记。

### 图例策略

- 画布上固定显示关键图例摘要，例如“颜色：社区”“节点大小：被引量”“双环：种子”。
- 完整图例与筛选选项仍放入侧栏抽屉。
- 单源／双源引用证据放在详情卡中用文字标签说明，不只用边颜色表达。
- 保持文字与图形语义一一对应；不要让一种颜色同时表示社区、证据可信度和选中状态。

### 关系语义

要在图谱和详情中区别：

- **直接引用**：论文 A 引用了论文 B。
- **共同参考文献／共被引**：网络相关性，不等于直接引用。
- **OpenCitations 补边**：说明源数据；若双方都确认，标为双源确认。
- **Semantic Scholar 意图／Influential**：只有接口返回数据时显示；不把它提升成因果影响证明。

## 三、让用户能理解“为什么出现这篇论文”

这是相较于继续增加图形类型，优先级更高的改进。

### 节点详情中的“关系与证据”模块

选中一篇论文后，清晰展示：

- 它与种子论文的关系类型。
- 关系方向，例如“种子引用了它”或“它引用了种子”。
- 证据来源：OpenAlex、OpenCitations、Semantic Scholar。
- 是否双源确认、是否为补充记录、是否因采样或预算而不完整。
- 有引用语境时展示原始上下文，并标明来源。
- 没有直接引用证据时，明确说这是图谱相似关系，而非引用关系。

避免把“相关度分数”作为单独理由；若展示分数，必须给出其构成和限定说明。

### 关系标签示例

- `直接引用 · OpenAlex`
- `直接引用 · 双源确认`
- `网络相似 · 共同参考文献`
- `引用意图 · Semantic Scholar`
- `Influential · Semantic Scholar 返回 true`
- `未找到引用语境`

## 四、把图谱发现接入笔记工作流

ResearchRabbit 的暂存思路适合借鉴，但本项目应优先做本地、低摩擦的 Obsidian 工作流，不引入账号或云同步。

### 建议分两步实施

**第一步：单篇保存**

从节点详情直接提供：

- 复制引用／BibTeX。
- 写入 Obsidian 笔记。
- 将论文信息、种子论文、关系和证据摘要一并写入。
- 对无法核验的模型判断保留明确标记，不能写成事实陈述。

**第二步：轻量暂存列表**

提供本次探索的“待读／暂存”列表，支持：

- 从图谱节点或列表项加入。
- 移除或标记已读。
- 导出为笔记或文献清单。
- 会话内暂存作为默认；是否持久化可以另行配置。

这样能让用户先探索，再整理，不必每次发现一篇论文就立即决定是否创建正式笔记。

## 五、改善先验、衍生与分析视图

### 先验工作／衍生工作

继续保留独立页签，并让标题更自解释：

- 先验：`种子引用的前置研究`
- 衍生：`后来引用种子的研究`

每页顶部用简短说明给出口径和限制：

- 结果来自当前图谱或查询范围。
- 列表排序依据是什么。
- 是否仅纳入当前已采样的引用关系。
- “相关／被引用”不等于学术影响。

每行显示的内容建议控制为：

- 年份、标题、来源。
- 命中的关系数量或关系类型。
- 来源与证据标记。
- 打开详情或加入暂存的操作。

### 分析页

桑基图与弦图继续保持次级，不改变默认图谱。

分析页应始终显示口径副标题，例如：

> 当前筛选范围内的直接引用；不代表完整学术史或实质影响。

另需提供：

- 图中论文数、引用边数、所选过滤条件。
- 无数据和数据稀疏时的解释性空状态。
- 点击图形区域后的论文列表或详情反馈。
- 桑基／弦图控件保持简单，不叠加更多分析指标。

## 六、渐进式布局与控制

当前布局、着色、年份过滤等功能齐全，但建议减少初始暴露的专业控制项。

### 视图预设

先提供少量预设，而不是立即增加大量自由配置：

1. **时间脉络**：突出年代顺序。
2. **研究主题**：突出社区分组。
3. **引用关系**：强调图内直接引用。

每个预设需要说明：

- 位置代表什么。
- 颜色代表什么。
- 哪些关系会显示。
- 是否影响数据筛选，还是只改变视觉呈现。

布局、着色、年份过滤继续可调，但可归入“视图设置”区域。低频设置默认收起。

### 年份控件

年份过滤应明确说明它会影响哪些部分：

- 只隐藏较晚节点，还是同时过滤列表和统计？
- 回放是否改变当前筛选？
- 缺失年份的论文如何处理？

建议统一让图谱、列表、分析视图使用同一套可见节点范围，并显示当前年份范围。

## 七、窄屏与嵌入式视图

Obsidian 侧栏宽度变化明显，嵌入图谱还会受笔记宽度和浮动布局影响，需要单独验收。

### 窄屏策略

- 页面窄于阈值时，垂直侧栏转换成横向滚动控件或菜单。
- 详情抽屉不应挤压图谱到无法操作的高度。
- 底部主导航可横向滚动，不能自动换行成多排高工具栏。
- 分析视图高度不足时允许滚动，但图形标题、口径说明和切换控件应保持可见。
- 图谱缩放按钮与嵌入式拖动手柄应避免互相遮挡。

### 最小验收宽度建议

至少在以下容器宽度检查：

- 320–360 px：窄侧栏／窄卡片。
- 400–520 px：常见笔记嵌入区。
- 700–900 px：宽侧栏或中等面板。
- 1000 px 以上：主工作区。

重点检查文字截断、按钮换行、抽屉遮挡、图谱尺寸和分析视图滚动。

## 八、视觉系统与无障碍

### 视觉系统

- 建立一套颜色 token：背景、次级面板、边框、主强调、选中、警告、错误、来源标签。
- 暖金色集中用于主操作和焦点，不要同时代表社区或数据来源。
- 控件的正常、悬停、选中、禁用状态保持一致。
- 长摘要与引用上下文采用舒适行高，降低密集信息的阅读压力。

### 无障碍与交互反馈

- 所有图例标记同时有文字，不依赖颜色识别。
- 选中节点、切换页签和当前过滤状态应能被键盘操作与辅助技术识别。
- Canvas 以外提供可操作的论文列表入口；不能把关键探索操作全部绑在画布点击上。
- 加载、失败、无结果、预算耗尽等状态用明确的文字说明，而不只是颜色变化。
- 按钮需要描述动作，不使用只靠图标猜含义的控件。

## 九、LLM 结果的视觉与文案规则

LLM 仍为可选项，关闭时：

- 不显示研究脉络页签。
- 不展示旧的 LLM 结果。
- 不发生模型请求。

开启时：

- 明确标为“模型辅助总结”。
- 将模型自评置信度与数据源证据分开呈现。
- 展示生成所依据的论文、引用方向和上下文来源。
- 显示覆盖范围、采样限制和时间。
- 不用“最重要”这类绝对标签；优先显示明确维度，如图内连接数、被引量、较新程度。
- 对证据文本不能逐条匹配原文的情况，不称为“已验证证据”；应标成“模型给出的依据说明”，提供原始来源链接供人工核对。

## 十、DOI 路径独立视图

按此前计划，路径功能不放入默认图谱工具栏，而作为命令面板独立入口。

### 结果需要明确说明

- 搜索的两个 DOI。
- 路径中的论文和引用方向。
- 路径长度。
- 使用的数据源。
- 搜索预算、最大深度、已检查节点数。
- 是否因预算耗尽而提前停止。
- 结果是“预算内找到的最短路径”，还是“预算内未找到路径”。

不能只显示一条路径并称“全局最短”。多条同长路径若预算允许，应支持切换查看；点击中间论文可加入当前图谱或暂存列表。

## 十一、分阶段实施与验收

### 阶段 0：基线与设计验收

- 采集当前主界面、窄侧栏、嵌入、详情、先验／衍生和分析页截图。
- 固定一组离线演示数据，覆盖双源引用、单源补边、缺少年份、无摘要、无意图数据和 LLM 关闭。
- 记录主要容器下的溢出、滚动和布局问题。

**通过标准：**形成可重复的视觉回归场景，不依赖在线数据变化。

### 阶段 1：信息层级和控件收纳

- 分离主导航与视图控制。
- 将导出操作收纳。
- 为筛选抽屉增加画布上的精简图例。
- 明确年份控件的范围和作用。

**通过标准：**新用户能找到构建、切换视图、筛选、查看详情和导出入口；工具栏不因窄宽度溢出。

### 阶段 2：关系证据与详情卡

- 统一展示关系类型、方向、数据源、单／双源状态。
- 在详情卡中展示“为什么出现”和可核验上下文。
- 对相似关系与直接引用做视觉区分。

**通过标准：**用户能从任意结果回答“它为何在这里、数据来自哪里、是否直接引用”。

### 阶段 3：图谱预设与分析视图

- 加入少量视图预设和解释。
- 统一图谱、列表、分析的过滤范围。
- 增强图表范围说明、空状态和点击反馈。

**通过标准：**切换视图不改变数据口径；分析图不会被误认为完整影响或学术史。

### 阶段 4：笔记工作流

- 节点详情直接写入笔记或复制引用。
- 加入本次会话暂存列表。
- 保存来源、关系说明和查询范围。

**通过标准：**从发现论文到形成可回溯笔记不需要重复查找来源。

### 阶段 5：DOI 路径入口

- 实现独立命令面板入口。
- 展示路径、方向、长度、来源和预算。
- 支持路径节点加入当前图谱或暂存。

**通过标准：**结果明确表达预算边界，不误称全局最短。

## 十二、建议的优先级

| 优先级 | 内容 | 原因 |
|---|---|---|
| P0 | 关系与证据说明、数据口径文案 | 直接影响用户是否正确理解图 |
| P1 | 导航与工具控件分层、窄屏验收 | 高频体验，减少操作混乱 |
| P1 | 图例摘要、关系颜色语义统一 | 提升可发现性和可读性 |
| P2 | 图谱视图预设 | 提供更直观的探索路径 |
| P2 | 单篇写入／暂存工作流 | 把探索成果带回笔记 |
| P3 | DOI 路径独立视图 | 有价值但应在核心浏览与证据解释稳定后做 |
| 不做 | 作者／机构网络 | 按既定范围排除 |

## 最终建议

实施顺序应是：**先明确关系证据和图例，再整理导航与响应式布局，然后做图谱预设和笔记工作流，最后推进 DOI 路径视图。**

这样可以先解决“图上信息是否可信、是否看得懂”，再扩展“还能探索什么”。相比同时上更多图表和控件，这条路线更贴合本项目的核心价值，也更容易通过小步迭代和截图回归验证。
